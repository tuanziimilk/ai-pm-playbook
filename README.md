# AI 产品经理 · Agent 系统六关

> 一个运营出身、正在转 AI 产品经理的人，把 Agent 系统拆成六关，一关一关写清楚。
>
> **不搬概念，只写我真跑过的取舍。** 没实操过的部分会明确标出来。

---

## 为什么写这个

市面上讲 Agent 的资料，多数停在**概念层**：RAG 是什么、ReAct 是什么、Function Calling 怎么工作。
但面试和落地真正会卡住人的是**下一层**：

> 「线上真出了这个问题，你从哪里查？怎么兜底？怎么证明修好了？」

这份笔记就是为那一层写的。每一关都按同一个结构：

```
图（机制怎么跑）
 → 三句话讲清
 → 母案例里长什么样（SEO Agent，贯穿六关）
 → 这张图能回答哪些问题 + 取舍怎么讲
```

**为什么用一个母案例贯穿六关**：六个例子读者记不住，一个案例走六遍能形成完整心智模型。
选 SEO Agent 是因为我做过几年 Google SEO 和内容增长，这个场景里的坑我知道是真的，不是编的。

## 我的实操边界（重要）

这份笔记不是从教程里抄的，但也不是每一块我都做过。**先说清边界，再谈内容**：

| 领域 | 我的实际经验 |
|---|---|
| 批量 LLM 流水线的异常兜底 | ✅ 做过。单次 1500 条的批量 AI 检测流，重试 / 降级 / 人工接管 / 断点续跑都真踩过 |
| 效果评测与基线对标 | ✅ 做过。用程序规则做基线（准确率 23%）量化 LLM 的实际提升；换模型时用同批样本对比，做到质量不掉、提速 40 倍、成本降 30% |
| 大规模数据治理 | ✅ 做过。程序预处理 + AI 仲裁 + 分流入库，跑过 9.5 万条 |
| 工具调用与安全护栏 | ✅ 做过。自然语言转 SQL 的取数链路，前置安全审查（仅单条 SELECT、拒写操作/DDL/多语句、只读账号执行） |
| 工作流编排 | ✅ 做过。n8n / Dify 的多步流水线与队列调度 |
| RAG 检索侧 | ✅ 做过。Embedding + 向量相似度的语义相关性判定 |
| RAG 生成侧 | 🟡 在补。检索做过，"检索后交 LLM 生成带引用答案"这半段还在做 demo |
| **多轮对话产品** | 🔴 **没做过**。我所有 AI 项目都是批处理 / 工具 / 中台形态，不是对话产品。对话状态管理、槽位填充、转人工这块目前是纸面理解 |
| 自主 Agent（模型自己决定下一步） | 🔴 没做过。做过的都是确定性工作流 + 带护栏的工具调用，**不硬称 Agent** |

**为什么把短板写在最前面**：因为这份笔记的价值在于"哪些是真跑过的"。
如果连边界都不说清，那它就退化成又一份概念搬运。

## 谁适合看

- 想转 AI 产品经理、概念背得差不多但不知道落地会卡在哪的人
- 被面试官追问过「那它失败的时候怎么办」并答不上来的人
- 需要一张能在实时压力下调出来的心智地图的人

**不适合**：想找完整教程的人（这是笔记，不是课程）；想找代码实现的人（这里只有设计和取舍）。
